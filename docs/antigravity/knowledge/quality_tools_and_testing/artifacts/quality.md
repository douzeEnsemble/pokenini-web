# Quality Tools and Testing

The `pokenini-web` project applies the same stringent quality checks as the rest of the ecosystem, with additional checks suitable for frontend output.

## Static Analysis & Linters

- **PHPStan**: Configured at `level: 9` (strictest). Command: `make phpstan`.
- **Psalm**: Used for secondary static analysis at a high level. Command: `make psalm`.
- **PHP-CS-Fixer**: Enforces coding standards. Commands: `make phpcsfixer` / `make phpcsfixer-fix`.
- **Deptrac**: Enforces architectural boundaries. Command: `make deptrac`.
- **PHPMD**: Detects code smells and complex code blocks. Command: `make phpmd`.
- **PHPInsights**: Used for comprehensive code quality review. Command: `make phpinsights`.
- **W3C HTML Validation**: Validates the HTML output generated by Twig. Command: `make w3c`.
- **Infra Linters**: `hadolint`, `dotenv-linter`, `dclint`, and `editorconfig-checker`. Command: `make infra-quality`.

## Testing Strategy

- **PHPUnit**: Used for Unit and Integration tests. Commands: `make tests-unit` (`tu`), `make tests-integration` (`ti`).
- **Browser Tests**: Employs **Symfony Panther** to run End-to-End (E2E) browser tests. Command: `make tests-browser` (`tb`).
- **Coverage**: Aims for **100% code coverage** (excluding browser tests group). Command: `make coverage`.
- **Mutation Testing (Infection)**: Aims for **100% Mutation Score Indicator (MSI)** and Covered MSI. Command: `make infection`.
- **API Mocking**: Integration and Browser tests mock the API using `moco.back`. The mocks are stored in `tests/resources/moco/Api` and `tests/resources/moco/OAuth`.

## Unified Quality Commands

The main workflow standard for developers is:
- `make cq` (code-quality): Runs all static analysis and linters (including w3c).
- `make t` (tests): Runs all PHPUnit tests.
- `make m` (measures): Runs coverage and infection checks.
- `make s` (security): Runs composer audit, symfony security checker, and OWASP Dependency Check (`make owasp-check`).

Workflow standard: `make cq t m s`.
